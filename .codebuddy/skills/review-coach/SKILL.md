# 复习教练：错题诊断与变式训练

## 概览

本仓库是「河南省 · 护理专业 · 中专单招考试」复习文档工程。用户多在**纸上**作答，再把每套试题下方的「订正反馈」块（按错因类型自评填空）作为批改情况交给 AI。本 skill 是这套流程的**消费端**：读取反馈 → 定位章节 → 诊断错因 → 沉淀疑点 → 出同类变式题供纸上再练。

它不替代而是衔接既有 skill：
- **danzhao-docs**：疑难点 / 错题本的文档格式、占位符与校验脚本均遵循其约定；
- **havefun-index**：把反馈里的题号 / 专题路由到具体章节；
- **auto-discover**：诊断出的高频专题写入 `错题本/疑难点.md`，二者共用同一文档结构。
- 交互强度默认「巩固 / 复习模式」（见 danzhao-docs「提问与交互约定」）：处理反馈时直接诊断、给结论与下一步，少追问、不抛选择题，仅在明显事实错误时轻点一句。

## 触发与输入

触发信号（命中其一即可）：
- 用户贴来或指向一块已填好的「### 订正反馈（套题名）」块；
- 用户说「帮我批改 / 讲讲这道题的错因 / 出几道同类题 / 复习教练 / 看看我哪类错得多」。

输入形式有两种，统一处理：
1. **结构化**：`题库.md` 中某套题的「订正反馈」块，已填 题号 / 具体情况 / 是否攻克；
2. **自由陈述**：用户口头描述「SX-003 我填错了，是因为……」，先按下面流程把它**规整成反馈块语义**再处理。

## 工作流程

1. **解析反馈**：提取每行有效信息——`问题类型`（错因）、`题号`、`具体情况 / 错因`、`是否攻克`。跳过全为 `待填写` 的空行；`是否攻克` 为 `🟢` 只是学习者的**自评（声称已攻克）**，不等于已掌握——按「验证题制」处理（见第 4 步），不跳过、不照单全收。
2. **逐行诊断**（对每条非空、未攻克的错因行）：
   - 用 havefun-index 把 `题号` 定位到章节（如 `SX-003` → `数学/函数/一次函数/知识点梳理.md`「二、知识点详解」；无编号时按用户描述的专题定位）。
   - 讲解该题为**什么错**：对应考点、易混点、规范表述；遵循 danzhao-docs「提问与交互约定」——**不默认用户表述正确**，若用户对错因的描述本身有偏差，先点明偏差再继续。
   - 以 danzhao-docs「可读性约定」的初一学力基准讲透原理：短句、常用词、术语首现配白话解释，必要时配类比 / 小表格。讲解末尾附一句「学法旁注」（审题 / 记忆 / 归因 / 整理，见 danzhao-docs「学法指导约定」），把"这题怎么改"升级为"这类怎么学"，并坚持成长型归因（只归因策略，不定性能力）。
   - 若该考点此前已讲过同类题仍错（同考点累计出错 ≥ 2），不原样重复讲解，转入「动态适配协议」换法处理。
3. **生成同类变式题**：针对该行错因，出 **1–2 道**新题（非原题），供纸上再练；题干遵循可读性约定（短句、常用词、超纲词标注释义）。难度遵循 danzhao-docs「大块知识点资料生成约定」三级标注（基础 / 进阶 / 拔高，可附 1–10 分值）。变式题默认**在对话中直接给出**（含答案与解析），不强制落库。
4. **写出评估区块**：诊断与变式题完成后，在**同一套题章节内、订正反馈块之后**写入「### 评估（套题名）」块，沉淀该套题的掌握结论。表格含：总体掌握（⬜/🟨/✅ 或 🟢）、主要错因（占错因比例）、建议优先级、同类变式题（已生成 N 道）、下次回顾间隔（按错因严重度建议 1/3/7/15 天之一）、下次回顾日期（评估写入日 + 间隔天数，作为 `study-session` 间隔复习召回锚点）；「总体掌握」以**验证结果**为准，而非用户自评。**验证题制**：对每行用户声称已攻克（`🟢`）的错因，以及用户请求改判已攻克的行，先出一道**基础难度、同考点不同情境的验证题**——做对才在评估中确认攻克；未做或未做对，在「结论」行写明「验证未过：<题号>，维持 ⬜」，该行按未攻克流程继续诊断。验证结果不擅自改写用户已填的「是否攻克」单元格；验证题计入「同类变式题」数量。模板与一致性校验（R19）见 danzhao-docs SKILL.md。
5. **沉淀疑点**：把反复出现的专题写入 `错题本/疑难点.md`（字段遵循 auto-discover：专题、学科、出现次数、首次/最近出现、关联问题摘要、对应章节链接、状态 ⬜）。其中「出现次数」按 auto-discover 的**权重分**累计——若本次含"验证未过"或错因占 `≥ 2` 行，应计较高权重（单信号即可达阈值）。同一专题已有记录则只更新权重分与摘要。将疑难点状态由 `⬜` 改为 `🟢`（已攻克）前，同样须先过一道验证题；未过只更新权重分与摘要，不改状态。
6. **可选回写错题本**：若用户明确某道具体错题，按 `错题本/README.md` 结构追加一行（编号 `CT-xxx`、科目、题目来源、错因类型、正确思路、状态 🔴）。错题本条目状态由 `🔴` 改 `🟢`（已攻克）前，同样须先过验证题。
7. **收尾总结**：用一两句话汇总——本次高频错因类型、最该优先回顾的章节、建议下次同类变式题的方向。

## 动态适配协议（同一考点反复出错时）

**原则：连续出错时改变教法，而不是原样重复。** 对已经卡住的学习者，重复同一讲法只会累积挫败感。

1. **触发条件**（命中其一即启动，不再按常规流程讲解）：
   - 同一考点的错因在本次反馈中占 ≥ 2 行，或刚生成的变式题再次做错；
   - 同一专题在 `错题本/疑难点.md` 的「出现次数」≥ 3 且状态仍为 `⬜`（升级细则见 auto-discover「升级规则」）。
2. **适配动作**（按顺序逐级尝试，每轮只用一招，生效即停）：
   - **降一级难度**：从进阶退回基础题，先确保单一知识点能做对，再逐级回升；
   - **换模态重讲**：文字讲解 → 图示 / 表格 → 生活实例类比 → 分步填空（把原题拆成带提示的小步骤，每步只要求一个小判断）；
   - **缩小步子**：一次只讲考点的一个环节，讲完立即用一道最小验证题检验，不做无检验的连环讲解。
3. **记录换法**：在 `错题本/疑难点.md` 对应行的「关联问题摘要」追加「已换讲法：<模态>（<日期>）」，避免下次会话重复同一讲法。
4. **换法前先稳情绪**：先用一句话具体肯定已掌握的部分（不空泛表扬），再说明换讲法的原因，如「这部分你已有进步，我们换一个更直观的方式再来一次」。
5. **升级上限**：同一专题换过 2 种讲法仍无进展，在该行摘要注明「建议真人老师讲解」，提示用户约学校老师或家教面授，AI 不无限循环。

## 与既有规则的关系

- **danzhao-docs**：写入疑难点 / 错题本时，文档头、占位符、表格列结构均须符合；编辑后运行：
  ```bash
  python .codebuddy/skills/danzhao-docs/scripts/manage.py all
  ```
  确保 ERROR 为 0 再交付。
- **havefun-index**：章节定位先查其 `references/index.md`，保持链接与索引一致。
- **auto-discover**：本 skill 是疑难点文档的写入方之一；写入格式与 auto-discover 完全一致，避免两处结构分歧。
- **不默认用户正确**：用户自述的错因可能是结果而非根因（如「算错了」实为「概念不清」），须辨析并给出规范归因。

## 变式题落库约定（可选）

若用户要求把变式题持久化：
- 追加到对应 `题库.md` 该套题下的「变式练习」小节（若该小节不存在则新建，遵循 R15 分类存放），题目编号沿用该科目前缀（如 `SX-011`）；
- 答案与解析同步写入同名 `题库解析.md` 对应章节（遵循 R17 题解分文档）；
- 写完后再次运行校验脚本。
