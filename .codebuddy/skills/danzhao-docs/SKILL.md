# 单招复习工程 文档生成约束

## Overview

本仓库是「河南省 · 护理专业 · 中专单招考试」复习文档工程，纯文档，不涉及代码。本 skill 规定所有文档的生成与修改规范：语言风格、占位符、事实安全、格式、流程与 git 约定。项目事实信息（考试构成、目录结构、编号前缀等）单独维护在 `references/project-facts.md`，本文件不重复。

## 硬性规则（不可违反）

1. **只用简体中文，用书面语**。禁止口语化表达、口水词、网络黑话（梗、谐音用语、职场黑话）。例：写「整理」不写「弄一下」，写「需核对」不写「得看看」，写「推荐」不写「安利」。
2. **只生成 Markdown 文档**。不创建代码、脚本、配置文件；除非用户明确要求（如 `.gitignore`、SKILL.md 本身）。
3. **政策与事实类信息禁止虚构**。考试时间、报名日期、分值、科目、分数线、院校录取规则等，一律不编造；不确定就写占位符，并在文档顶部加来源提示：

   ```markdown
   > ⚠️ 以下内容需以当年河南省教育考试院 / 目标院校官方发布的单独招生简章与考试大纲为准。
   ```

4. **医学知识点按主流教材常识整理**（解剖、生理、护理基础的章节框架与常用正常值），但涉及具体院校考试范围的表述仍按第 3 条处理。
5. **不重写用户已有内容**。用最小改动完成编辑，保持用户原有结构和措辞，除非用户明确要求重构。

## 格式约定

1. **文件头**：每个文档第一行是 `# 标题`，标题与文件名一致。
2. **掌握程度标记**（知识点梳理、题库、实操面试统一使用）：
   - `⬜` 未学 / `🟨` 学习中 / `✅` 已掌握
   - 错题本状态：`🔴` 未攻克 / `🟢` 已攻克
3. **占位符**：`待填写`（需用户决策的信息）、`待添加`（待收录的内容）、`待补充`（待完善的列表）。表格行不允许整行无占位符的空白单元格，每个模板行至少包含一个占位符；复习计划中的日程任务表除外。
4. **表格优先**：结构化信息（计划、清单、登记表、对比）一律用 Markdown 表格；表头分隔行不可省略。
5. **交叉引用**：文档间跳转用相对路径链接，如 `[解剖学基础](../解剖学基础/知识点梳理.md)`。
6. **章节顺序**：`## 一、` 起用中文数字递增；章节内条目用无序列表。
7. **条目编号**：题库、错题本条目用「前缀 + 三位序号」（如 `HL-001`）。前缀与科目的对应关系见 `references/project-facts.md`；新增科目时先在事实文件中登记前缀，再使用。
8. **分类存放**（仅 `知识点梳理.md`、`题库.md` 适用）：内容须按维度分门别类组织，不得散落堆放在文档末尾。
   - 至少建立 2 个二级分类章节（如知识点按「章节 → 考点」、题库按「章节 / 题型」），且每个分类章节下须有内容，不得存在空分类。
   - 新增内容按归属归入既有分类；需新增分类时先建章节标题，再把内容放进去；确需调整分类时整体迁移，不留下空壳分类。
   - 该规则由校验器 R15 强制检查，判定标准：二级章节数 ≥ 2 且各分类章节均非空。
9. **文档头元数据**（适用于除 `README.md` 外的所有内容文档）：在标题下方紧接一个「文档头」表格，登记四项元数据，便于检查与维护。
   - 格式：
     ```
     | 项目 | 内容 |
     | --- | --- |
     | 状态 | ⬜ 未整理 / 🟨 整理中 / ✅ 已完善 |
     | 创建时间 | YYYY-MM-DD |
     | 学科 | 数学 / 语文 / 英语 / 护理专业 / 复习计划 / 政策资讯 |
     | 分类 | 知识点梳理 / 题库 / 考试大纲 / 报名与志愿 / 总体规划 / 节点安排 / 事实依据 |
     ```
   - 字段取值说明：
     - **状态**：文档整体完成度，用约定标记 `⬜` `🟨` `✅`，区别于知识点级的「掌握程度」。
     - **创建时间**：文档建立日期，格式 `YYYY-MM-DD`；既有文档补录时记为补录日期。
     - **学科**：按仓库一级分类填写（护理专业下的解剖/生理/护理学基础归入「护理专业」）。
     - **分类**：文档的职能类别，与 `references/project-facts.md` 目录结构与 `havefun-index` 索引表的二级分类保持一致。
   - 该规则由校验器 R16 强制检查：标题后至首个二级标题之间须出现「状态 / 创建时间 / 学科 / 分类」四项字样。
10. **习题与答案解析分文档**（适用于 `题库.md` 等习题类文档）：习题文档只收录题干，答案与详细解析不得内联在同一文档，须归入同名解析文档（命名如 `题库解析.md`），按题号对应；每个答案之后须紧跟详细解析。
   - 该规则由校验器 R17 强制检查：文件名为 `题库.md` 的文档中不得出现内联的答案 / 解析标记（如 `**答案**` / `**解析**`），出现即报 ERROR，提示将答案与解析迁移至同名解析文档。

11. **套题订正反馈模板**（适用于 `题库.md` 中含题目的每套试题）：用户多在纸上作答，故每套试题下方须预留一块「订正反馈」供其按错因类型自评填空，再把该块内容作为批改情况交给 AI（由 `review-coach` skill 消费，做诊断、记录与同类题生成）。
   - 触发范围：二级标题含「测验 / 专项 / 模拟卷 / 真题 / 自测 / 练习」且章节内含 `### 第 N 题` 的套题，必须在本章节内放置该块。
   - 模板（错因类型与 `错题本/README.md` 的错因类型一致）：

     ```markdown
     ### 订正反馈（<套题名>）

     | 问题类型 | 题号 | 具体情况 / 错因 | 是否攻克 |
     | --- | --- | --- | --- |
     | 概念不清 | 待填写 | 待填写 | ⬜ |
     | 计算失误 | 待填写 | 待填写 | ⬜ |
     | 思路错误 | 待填写 | 待填写 | ⬜ |
     | 审题偏差 | 待填写 | 待填写 | ⬜ |
     | 知识遗忘 | 待填写 | 待填写 | ⬜ |

     补充（非填空，可写几句）：待填写
     ```
   - 行首「问题类型」为固定表头，其后五行须为上述五类错因；「是否攻克」用 `⬜` / `🟢`。
   - **评估区块（AI 回填，与订正反馈配套）**：你提交订正反馈后，`review-coach` 处理完诊断与同类变式题，须在**同一套题章节内、订正反馈块之后**写入一块「评估」，沉淀该套题的掌握结论（套题级，便于一眼回看）。模板：
     ```markdown
     ### 评估（<套题名>）

     | 维度 | 评估 | 说明 |
     | --- | --- | --- |
     | 总体掌握 | 🟨 学习中 | 基于本次反馈 |
     | 主要错因 | 待填写 | 占错因比例 |
     | 建议优先级 | 待填写 | 先攻主要错因 |
     | 同类变式题 | 待填写 | 已生成 N 道 |
     | 下次回顾 | 待填写 | 建议间隔天数 |

     结论：待填写
     ```
   - 评估区块为 AI 处理反馈后的**产出**，文档初建时可不存在，故不纳入 R18 的强制创建校验；其「总体掌握」须与订正反馈的「是否攻克」保持一致：反馈全行 `🟢` 时总体掌握应标 `✅`/`🟢`，否则不应标 `✅`。该一致性由校验器 **R19（WARN 级）** 检查。
   - 该规则由校验器 R18 强制检查：套题章节缺「### 订正反馈」块，或其表格缺少任一错因类型行，均报 ERROR。

## 文档目录与模块拆分约定

本工程以「知识单元」为文档组织的基本单位。每个知识单元须配齐**四件套**，文件名固定：

- `知识点梳理.md`：大纲 + 详解 + 习题（按「大块知识点资料生成约定」）
- `题库.md`：题干 + 三级难度 + 订正反馈块（R18）
- `题库解析.md`：答案与详细解析（R17，题解分文档）
- `知识点目录.md`：本章节级快速跳转目录（锚点链接）

校验器（R15/R17/R18/R19/R09）均按**文件名**命中，故无论层级多深，子目录内这四件套文件名保持一致即可，无需改规则。

### 何时拆子目录

出现以下任一情况时，应**按模块拆子目录**，而非继续在同一文件里向上堆叠：

- 单文件四件套已臃肿，单个考点无法在文件中独立成「件」（如一次函数被压在大文件一个小节里、没有独立目录）；
- 学科覆盖多个并列模块（如数学含 数与式 / 方程 / 函数 / 几何 / 统计）。

### 拆分粒度（两级）

1. **一级：学科 → 大模块**。学科根目录下按大模块建子文件夹，如 `数学/{代数,函数,几何,统计}/`，每个文件夹是独立的四件套单元。
2. **二级：模块 → 子模块**。若某模块内部仍含多个并列专题，继续拆子文件夹，如 `函数/{一次函数,二次函数}/`，每个子模块仍是自洽的四件套单元。

### 顶层只留索引与共用文件

学科根目录**只放**：

- `知识点目录.md`：按模块跳转的学科索引（顶层章节用中文数字编号，如「## 一、代数」，满足 R09）；
- 学科级共用文件，如 `常用公式速查.md`、`薄弱点记录.md`。

具体内容下沉到模块 / 子模块文件夹，避免根目录出现又大又扁的单文件四件套。

### 命名与编号

- 子目录内的四件套文件名**保持不变**（`知识点梳理.md`、`题库.md` 等），便于校验器按文件名命中。
- 题号前缀：单模块内可沿用学科前缀（如 `SX-001`）；若多模块并存为避免重号，可按模块细分前缀（如 `SX-1F-`、`SX-2Q-`），并在 `references/project-facts.md` 编号前缀表中登记。

### 与索引 / 同步

拆子目录后必须同步：

- 根 `README.md` 目录树：每个新增 `.md` 都须登记（R11）；
- `havefun-index/references/index.md`：意图表与章节列表指向新路径；
- `references/project-facts.md`：文件清单与目录结构更新。

> 例外：学科体量小（如英语、语文当前仅单文件四件套）时，可不拆子目录，直接在学科根目录维护四件套即可。


## 校验脚本（强制执行）

规范不依赖自觉，由脚本硬校验。每次新建或修改文档后必须运行：

```bash
python .codebuddy/skills/danzhao-docs/scripts/manage.py all
```

- 修复所有 ERROR 后方可交付；WARN 尽量修复。
- `manage.py docs [路径]`：只校验文档；`manage.py scripts`：只校验脚本自身；`manage.py list`：列出全部文档规则（R01–R19）。
- 校验器位于 `.codebuddy/skills/danzhao-docs/scripts/`：`check_docs.py` 实现文档规则 R01–R19，口水词词表在 `scripts/data/colloquial-words.txt`，黑话词表在 `scripts/data/slang-words.txt`。
- R14 黑话检测：命中黑话词表报 ERROR；新发现的疑似黑话（拼音缩写型新梗）由脚本自动登记到黑话词表（替换词记为「待确认」，WARN），需人工确认：是则补书面替换词并改写文档，否则改为「!词=>保留」忽略。
- 新增文档规则：在 `check_docs.py` 的 `RULES` 注册并挂载到 `FILE_RULES`，然后运行 `manage.py scripts` 确认脚本自身合规。
- 修改任何脚本后，必须运行 `manage.py scripts` 并通过自校验（S01–S09）。
- 本 skill 与 `references/project-facts.md` 只写事实：规则编号、脚本行为、文件用途须与实际情况一致，词表替换词仅作书面改写建议；无把握的词义不收录，宁缺毋滥。

## 新建文档流程

1. 读取 `references/project-facts.md`，确认归属目录、命名与编号前缀。
2. 套用「四件套」模板结构（详见「文档目录与模块拆分约定」）：每个知识单元配齐 `知识点梳理.md` / `题库.md` / `题库解析.md` / `知识点目录.md` 四件套（文件名固定，校验器按文件名命中）；学科体量变大时按模块拆子目录，而非堆叠到同一文件。
   - `知识点梳理.md`：`# 标题` → 文档头（状态 / 创建时间 / 学科 / 分类）→ 按章节的考点列表（每个章节下再按考点分门别类）→「常用数据/正常值速查表」（如适用）→「薄弱点记录」表。
   - `题库.md`：`# 标题` → 文档头（状态 / 创建时间 / 学科 / 分类）→ 使用说明 → 按章节/题型分类收录 → 高频考点自测 → 真题/模拟卷登记表；题目统一归入对应分类章节，不得散落堆放在文档末尾。
   - `题库解析.md`：与 `题库.md` 同名，只放答案与详细解析（R17 题解分文档）。
   - `知识点目录.md`：本章节级快速跳转目录，列出本单元及下属章节 / 子模块的跳转链接，相对路径须正确。
3. 属政策资讯类的文档，先加顶部 ⚠️ 来源提示。
4. 同步更新根 `README.md` 目录树与快速入口，目录结构有变化时同步更新 `references/project-facts.md` 与 `havefun-index/references/index.md`（意图表、章节列表指向新路径）。
5. 向用户说明新增/修改了哪些文件、有哪些待填写项。

## 修改既有文档流程

1. 先 `read_file` 读取目标区域，再 `replace_in_file` 精准替换；同一文件连续替换不超过 3 次，超出则重新读取。
2. 保留原有表格列结构；需要新列时追加在表尾，不随意删列。
3. 修改涉及科目范围变化时（如换专业、确认目标院校），检查 `README.md`、`政策资讯/考试大纲.md`、`复习计划/总复习计划.md`、`错题本/README.md` 四处是否需同步，并更新 `references/project-facts.md` 中的事实。

## 大块知识点资料生成约定

当用户要求按「范围」系统整理某一大块知识点（如「一次函数」「三角形全等」「细胞」）时，生成的资料须按以下三段组织，便于从总览到精通的递进复习：

1. **知识点大纲**：以层级列表（一级：章节 / 主题；二级：考点）列清该范围全部知识点，作为总览与检索入口。大纲须与分类存放规则（R15）一致，按既有分类章节归口。
2. **知识点详解**：紧扣大纲逐条展开，每个考点独立成小节。讲解按**探究式、循序渐进**组织——
   - **循序渐进**：从已知或具体情境出发，由浅入深、由表及里；先建立直观认识，再抽象出概念与规律，最后归纳通法与易错点。逻辑连贯、不跳跃、不堆砌。
   - **探究式展开**：以问题或现象为起点，通过举例、观察、对比、类比、画图、列表等方式引导读者自行发现规律（如「改变 k 的符号，图象会怎样变化？」），再归纳定义、性质与结论；避免直接抛出结论式说教。
   - 每个考点按「提出问题 / 呈现现象 → 探究过程 → 归纳结论 → 典型样例」推进，样例须紧贴所探究的规律；**结尾附「结论速记」一句**（提炼本考点的定义 / 性质 / 公式，供快速查阅，与 `常用公式速查.md` 呼应），兼顾"怎么来的"与"一秒查到"。
   - **避免伪探究**：探究须提真实问题、走真实推理路径，结论由探究自然得出；不得把既定结论套进「提出问题→探究→归纳」的空壳模板（此即翻译腔的变体），也不得为凑篇幅堆砌无意义的设问。
3. **对应习题**：每个考点配套一组习题，统一归入该考点的习题小节，题目编号沿用该科目条目前缀（如 `SX-001`）。
   - 习题须贴近考点的**原理本质**，重在理解与迁移，而非机械套公式；
   - 若某考点涉及「多选 / 多次选择」类考查，须拆分为多个独立单选题，每题只考查其中一个选项点，再分别标注难易级别，不在单题内让用户一次多选；
   - 每道题标注**难易级别**，采用三级：
     - **基础**：贴近原理、理解即可完成；
     - **进阶**：有点难度，需要一定的分析与转化；
     - **拔高**：高难度，需要综合推理或多步推导。
   - 可在级别后附 1–10 的难度分值（数值越大越难），格式示例：`【进阶｜难度 6】`、`【拔高｜难度 9】`；标注须与题目一一对应，不得遗漏。
   - **题量建议**：以「考点」为最小单元，每考点 2–3 题（1 道基础 + 1 道进阶；易混 / 易错考点再加 1 道拔高）。整个分类（章节）再配 1–2 道跨考点综合拔高题。粗略对应：小类（单一概念）3–5 题、中类（一节 / 一小章）6–10 题、大类（整章）10–15 题。
   - **难度配比**：基础 : 进阶 : 拔高 建议 **5 : 3 : 2**（基础保覆盖与熟练，进阶练转化，拔高验综合）；难点章节可放宽至 4 : 4 : 2。每题须按上述三级标注难易级别，配比以该分类全部习题计。
   - **题目与答案解析分文档存放**：习题文档（如 `题库.md`）只写题干，不写答案与解析；答案与详细解析单独归入同名解析文档（如 `题库解析.md`），按题号对应。每个答案之后须紧跟详细解析，解析须循序渐进讲清推导过程与思路，使读者能独立看懂。该分离规则由校验器 R17 强制检查（题库类文档不得内联 `**答案**` / `**解析**` 标记）。

> 说明：用户原话中「7 分 / 2 分 / 1 分」的难度对应关系不统一（7 与 2 均注「有点难度」、1 注「高难度」），此处已规范为「三级难度 + 可选 1–10 分值（越大越难）」。如需沿用特定数值映射，请明确后补充到本约定。

## 提问与交互约定

处理用户提出的疑问或任务时，按以下流程进行，避免默认用户表述即正确：

1. **不默认用户正确**：用户的说法、术语或预设不一定准确、完备，不得未经辨析就顺从其字面表述直接执行。
2. **转化为学界问题**：先理解用户意图，将其转化为该学科 / 领域里真实存在的学术问题（如概念界定、定理适用条件、常见误区、表述规范等），而不是直接把用户的说法当作既定前提。
3. **先解析、再认可、后执行**：
   - 先用简短文字解析用户问题背后的真实问题，并给出你的理解（必要时指出其表述与学界通识的偏差，给出规范表述）；
   - 当你的理解与用户原意存在差异时，先点明该差异再继续，而非默默套用可能不准确的预设；
   - 完成解析与确认（或得到用户认可）后，再按原指令继续生成、修改或整理文档内容。
4. **细节未定时化为单个选择**：当用户的提问存在较多未确定的细节或意图不明时，不得抛出一堆开放式问题让用户逐项作答；应把需要澄清的事项逐个转化为单个选择题——一次只问一个问题，并给出 2–4 个明确选项（必要时附「其他，请说明」），由用户点选即可，降低回答负担。待关键选择确定后，其余细节按惯例默认值处理，不再反复追问。

> 说明：本约定要求「解析并认可后再继续」，目的是校正可能的表述偏差；若解析后无实质分歧，则直接继续，不因循拖延。
