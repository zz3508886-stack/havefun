# 单招复习工程 文档生成约束

## Overview

本仓库是「河南省 · 护理专业 · 中专单招考试」复习文档工程，纯文档，不涉及代码。本 skill 规定所有文档的生成与修改规范：语言风格、占位符、事实安全、格式、流程与 git 约定。项目事实信息（考试构成、目录结构、编号前缀等）单独维护在 `references/project-facts.md`，本文件不重复。

## 硬性规则（不可违反）

1. **只用简体中文，用书面语**。禁止口语化表达、口水词、网络用语。例：写「整理」不写「弄一下」，写「需核对」不写「得看看」。
2. **只生成 Markdown 文档**。不创建代码、脚本、配置文件；除非用户明确要求（如 `.gitignore`、SKILL.md 本身）。
3. **政策与事实类信息禁止虚构**。考试时间、报名日期、分值、科目、分数线、院校录取规则等，一律不编造；不确定就写占位符，并在文档顶部加来源提示：

   ```markdown
   > ⚠️ 以下内容需以当年河南省教育考试院 / 目标院校官方发布的单独招生简章与考试大纲为准。
   ```

4. **医学知识点按主流教材常识整理**（解剖、生理、护理基础的章节框架与常用正常值），但涉及具体院校考试范围的表述仍按第 3 条处理。
5. **不重写用户已有内容**。用最小改动完成编辑，保持用户原有结构和措辞，除非用户明确要求重构。

## 格式约定

1. **文件头**：每个文档第一行是 `# 标题`，标题与文件名一致。
2. **掌握程度标记**（知识点梳理、题库、实操面试统一使用）：
   - `⬜` 未学 / `🟨` 学习中 / `✅` 已掌握
   - 错题本状态：`🔴` 未攻克 / `🟢` 已攻克
3. **占位符**：`待填写`（需用户决策的信息）、`待添加`（待收录的内容）、`待补充`（待完善的列表）。表格行不允许整行无占位符的空白单元格，每个模板行至少包含一个占位符；复习计划中的日程任务表除外。
4. **表格优先**：结构化信息（计划、清单、登记表、对比）一律用 Markdown 表格；表头分隔行不可省略。
5. **交叉引用**：文档间跳转用相对路径链接，如 `[解剖学基础](../解剖学基础/知识点梳理.md)`。
6. **章节顺序**：`## 一、` 起用中文数字递增；章节内条目用无序列表。
7. **条目编号**：题库、错题本条目用「前缀 + 三位序号」（如 `HL-001`）。前缀与科目的对应关系见 `references/project-facts.md`；新增科目时先在事实文件中登记前缀，再使用。

## 校验脚本（强制执行）

规范不依赖自觉，由脚本硬校验。每次新建或修改文档后必须运行：

```bash
python .codebuddy/skills/danzhao-docs/scripts/manage.py all
```

- 修复所有 ERROR 后方可交付；WARN 尽量修复。
- `manage.py docs [路径]`：只校验文档；`manage.py scripts`：只校验脚本自身；`manage.py list`：列出全部文档规则（R01–R13）。
- 校验器位于 `.codebuddy/skills/danzhao-docs/scripts/`：`check_docs.py` 实现文档规则 R01–R13，口水词词表在 `scripts/data/colloquial-words.txt`。
- 新增文档规则：在 `check_docs.py` 的 `RULES` 注册并挂载到 `FILE_RULES`，然后运行 `manage.py scripts` 确认脚本自身合规。
- 修改任何脚本后，必须运行 `manage.py scripts` 并通过自校验（S01–S08）。

## 新建文档流程

1. 读取 `references/project-facts.md`，确认归属目录、命名与编号前缀。
2. 套用对应模板结构：
   - `知识点梳理.md`：`# 标题` → 按章节的考点列表 →「常用数据/正常值速查表」（如适用）→「薄弱点记录」表。
   - `题库.md`：`# 标题` → 使用说明 → 按章节/题型收录表 → 高频考点自测表 → 真题/模拟卷登记表。
3. 属政策资讯类的文档，先加顶部 ⚠️ 来源提示。
4. 同步更新根 `README.md` 目录树与快速入口，目录结构有变化时同步更新 `references/project-facts.md`。
5. 向用户说明新增/修改了哪些文件、有哪些待填写项。

## 修改既有文档流程

1. 先 `read_file` 读取目标区域，再 `replace_in_file` 精准替换；同一文件连续替换不超过 3 次，超出则重新读取。
2. 保留原有表格列结构；需要新列时追加在表尾，不随意删列。
3. 修改涉及科目范围变化时（如换专业、确认目标院校），检查 `README.md`、`政策资讯/考试大纲.md`、`复习计划/总复习计划.md`、`错题本/README.md` 四处是否需同步，并更新 `references/project-facts.md` 中的事实。

## 自查清单（提交前逐项核对）

- [ ] 全文简体中文、书面语，无口语化表述
- [ ] 无虚构的政策/考试信息，占位符与 ⚠️ 提示到位
- [ ] 标题、编号前缀、状态标记、占位符符合格式约定
- [ ] 表格行列完整，交叉引用链接有效
- [ ] `README.md` 与文档实际结构一致
- [ ] 未擅自改动用户已有内容
- [ ] 已运行 `python .codebuddy/skills/danzhao-docs/scripts/manage.py all` 且 ERROR 为 0

## Git 提交约定

- 仅当用户明确要求「提交」时才执行 git commit。
- 提交信息用中文、动宾结构，说明这一版做了什么，如「确定专业方向：河南护理单招，建立护理专业目录」。
- 不主动 push、不改 git config、不重写历史。

## Resources

### scripts/

- `manage.py`：脚本管理器。`scripts` 校验脚本自身（S01–S08），`docs [路径]` 校验文档规范，`all` 两者都执行，`list` 列出文档规则。
- `check_docs.py`：文档规范校验器，实现 R01–R13。
- `lib.py`：共享的问题记录与报告格式，供两个入口复用。
- `data/colloquial-words.txt`：口水词词表（R01 使用），格式为「词=>替换词」。

### references/

- `project-facts.md`：项目事实快照——工程定位、考试构成、目录结构与文件用途、编号前缀表、政策信息来源。首次在本仓库工作、或不确定文件该放哪里/编号用什么前缀时，先读取此文件。事实发生变化（确定目标院校、考试科目确认、目录调整）时，同步更新该文件。其中的编号前缀表被 R10 规则解析，修改时保持「| 前缀 | 科目 | 示例 |」表格格式。
