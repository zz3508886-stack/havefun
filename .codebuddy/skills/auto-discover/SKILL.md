# 自动发现：疑难点归集

## 概览

本仓库是「河南省 · 护理专业 · 中专单招考试」复习文档工程。本 skill 让助手在对话过程中监测用户提问的学科与专题分布，当某一专题被反复问及时（"问得多了"），把该专题写入 `错题本/疑难点.md`，便于日后重点复习。它把"反复困惑之处"从聊天流中沉淀为可复习的结构化记录。

**已接线说明**：本流程不再依赖易失的会话记忆，而是以 `错题本/疑难点.md` 本身作为跨会话的计数真值源；并由 `study-session` 在每一轮学习交互中统一调用，因此"自动发现"会真正随对话运转，而非停留在定义。

## 工作流程

1. **归类**：每次用户提问，先用 havefun-index 的意图词汇与学科内容目录判断它归属的学科与专题（如「一次函数」「生命体征评估」）。无法精确归类时，按用户原意提炼一个稳定的专题关键词，避免同一专题被拆成多个名字。
2. **计数（持久化，以疑难点.md 为真值源）**：
   - **先读取 `错题本/疑难点.md` 中该专题已有「出现次数」作为跨会话基数**；
   - 在本会话内维护一张计数表——`专题 → 出现次数、首次提问时间、最近提问摘要`；
   - 把"文件已记次数 + 本会话新增次数"相加，即为累计次数。这样计数落盘，不依赖易失的 `update_memory`（`update_memory` 仅作可选缓存，丢失也不影响历史计数）。
3. **触发阈值**：当某专题累计出现次数达到阈值（默认 2 次，即"问了不止一次"），自动在 `错题本/疑难点.md` 写入或更新一条记录。阈值首次使用前，按「提问与交互约定」转化为单个选择题与用户确认（如 2 次 / 3 次 / 由我判断）。
4. **写入 / 更新疑难点文档**（严格按 danzhao-docs 规范）：
   - 若该专题尚无记录：在「一、疑难点记录」表追加一行，字段含——专题、学科、出现次数、首次出现（日期）、最近出现（日期）、关联问题摘要、对应章节链接（指向 havefun-index 定位到的知识点梳理/题库章节）、状态（⬜ 待攻克 / 🟢 已攻克）。
   - 若该专题已有记录：只更新「出现次数」「最近出现」「关联问题摘要」「对应章节链接」，不新增重复行。
   - **去重规则**：以「专题 + 学科」作为唯一键；同一键只存在一行，绝不因多次触发而生成重复行。
   - 未知字段用 `待填写` / `待补充` 占位，不得留空行。
5. **主动告知**：写入（或更新）后用一句话提示，例如"已将『一次函数』记入疑难点（已问 3 次），可在 `错题本/疑难点.md` 重点查看"。

## 与既有规则的关系

- **danzhao-docs**：疑难点文档的标题、文档头（状态 / 创建时间 / 学科 / 分类）、表格格式、占位符均须符合其约定；编辑后运行 `python .codebuddy/skills/danzhao-docs/scripts/manage.py all` 确保 ERROR 为 0。
- **havefun-index**：定位专题对应章节时先查其索引表，保持章节链接与索引一致。
- **study-session**：本 skill 的归类+计数+阈值写入流程由它在每轮交互中调度，使自动发现真正运转。
- **review-coach（写入契约）**：两者都触及 `错题本/疑难点.md`，须避免重复造行。约定如下——
  - 本 skill 负责**按频率建/更疑难点行**（专题、学科、出现次数、摘要、章节链接、状态）；
  - review-coach 在具体错题诊断时，只**更新已有疑难点行的「关联问题摘要」**（补充错因/易混点），不新建行；具体错题的明细另记入 `错题本/README.md`（CT 行）。
- **提问与交互约定**：不默认用户表述正确；用户关于某专题的说法如有偏差，先解析并给出规范表述，再记入疑难点。
- **不默认用户正确**：若用户反复提问源于概念误解，疑难点摘要应写明"易混点"而非照抄用户原话。

## 疑难点文档结构

`错题本/疑难点.md` 含：文档头 + 「一、疑难点记录」表（上述字段）+ 「二、复习建议」。新增记录只动记录表，不改动复习建议。
