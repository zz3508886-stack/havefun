# 自动发现：疑难点归集

## 概览

本仓库是「河南省 · 护理专业 · 中专单招考试」复习文档工程。本 skill 让助手在对话过程中监测用户提问的学科与专题分布，并按**权重**把"真困惑"沉淀为可复习的结构化记录：普通提问 `+1`、测验验证未过或错题命中 `+2`（强信号），累计达阈值即写入 `错题本/疑难点.md`。它比纯计数更贴近真实薄弱度——一次测验失败胜过多次随口提问。

**已接线说明**：本流程不再依赖易失的会话记忆，而是以 `错题本/疑难点.md` 本身作为跨会话的计数真值源；并由 `study-session` 在每一轮学习交互中统一调用，因此"自动发现"会真正随对话运转，而非停留在定义。

## 工作流程

1. **归类**：每次用户提问，先用 havefun-index 的意图词汇与学科内容目录判断它归属的学科与专题（如「一次函数」「生命体征评估」）。无法精确归类时，按用户原意提炼一个稳定的专题关键词，避免同一专题被拆成多个名字。
2. **计分（持久化，以疑难点.md 为真值源）**：本 skill 不再只数"问了几遍"，而是按**权重**累计，使"真不会"（测验失败）比"多问一遍"更快被标记为疑点。
   - **先读取 `错题本/疑难点.md` 中该专题「出现次数」列作为跨会话基数**（此列在本体系中即**权重分**，非纯提问次数）；
   - 在本会话内维护一张计数表——`专题 → 权重分、首次出现时间、最近出现摘要`；
   - 每次信号累加权重：
     - 用户就该专题提问一次：`+1`；
     - 该专题在某套题「验证题未过」，或命中 `错题本/README.md` 的 CT 行错因：`+2`（强信号——一次测验失败胜过多次提问）；
     - 同一考点在 review-coach 诊断中占 `≥ 2` 行错因：`+2`；
   - 把"文件已记权重分 + 本会话新增权重分"相加，即为累计权重分。计数落盘，不依赖易失的 `update_memory`（`update_memory` 仅作可选缓存，丢失也不影响历史计数）。
3. **触发阈值**：当某专题累计权重分达到阈值（默认 `2` 分），自动在 `错题本/疑难点.md` 写入或更新一条记录。由于"验证未过"单次即 `+2`，意味着**一次测验失败即可直接记入疑点**，比单纯多问一遍更敏感、更贴近真实薄弱度。阈值首次使用前，按「提问与交互约定」转化为单个选择题与用户确认（如 `2` 分 / `3` 分 / 由我判断）。
4. **写入 / 更新疑难点文档**（严格按 danzhao-docs 规范）：
   - 若该专题尚无记录：在「一、疑难点记录」表追加一行，字段含——专题、学科、出现次数、首次出现（日期）、最近出现（日期）、关联问题摘要、对应章节链接（指向 havefun-index 定位到的知识点梳理/题库章节）、状态（⬜ 待攻克 / 🟢 已攻克）。
   - 若该专题已有记录：只更新「出现次数」「最近出现」「关联问题摘要」「对应章节链接」，不新增重复行。
   - **去重规则**：以「专题 + 学科」作为唯一键；同一键只存在一行，绝不因多次触发而生成重复行。
   - 未知字段用 `待填写` / `待补充` 占位，不得留空行。
5. **主动告知**：写入（或更新）后用一句话提示，例如"已将『一次函数』记入疑难点（已问 3 次），可在 `错题本/疑难点.md` 重点查看"。

## 升级规则（同一专题反复出现仍待攻克时）

计数达到阈值只说明「这里反复出问题」，不说明「重复同一讲法就能解决」。当某专题出现以下情况时，按「改变教法而非重复」原则升级处理：

1. **触发**：同一专题累计权重分 ≥ 3 且状态仍为 `⬜`；或含至少一次"验证未过"信号后仍再次被问及；或本会话内已换过讲法、该专题仍再次被问及。
2. **动作**：
   - 先按上述流程正常更新该行的次数、日期与摘要，并在「关联问题摘要」追加「已换讲法：<模态>（<日期>）」；
   - 向用户明示情况并交出选择权：「这个专题已经第 N 次卡住了，我们换个方式。你更适应哪种讲法：文字讲解 / 图示表格 / 生活例子类比 / 分步填空？」（按 danzhao-docs「提问与交互约定」化为单个选择题，由学习者选定适配的讲法）；
   - 在疑难点行中注明已尝试与待尝试的讲法，供后续会话续接，不从头再讲。
3. **升级上限**：同一专题累计换过 2 种讲法仍无进展，在该行摘要注明「建议真人老师讲解」，提示用户约学校老师或家教面授，AI 不无限循环。

## 与既有规则的关系

- **danzhao-docs**：疑难点文档的标题、文档头（状态 / 创建时间 / 学科 / 分类）、表格格式、占位符均须符合其约定；编辑后运行 `python .codebuddy/skills/danzhao-docs/scripts/manage.py all` 确保 ERROR 为 0。
- **havefun-index**：定位专题对应章节时先查其索引表，保持章节链接与索引一致。
- **study-session**：本 skill 的归类+计数+阈值写入流程由它在每轮交互中调度，使自动发现真正运转。
- **review-coach（写入契约）**：两者都触及 `错题本/疑难点.md`，须避免重复造行。约定如下——
  - 本 skill 负责**按频率建/更疑难点行**（专题、学科、出现次数、摘要、章节链接、状态）；
  - review-coach 在具体错题诊断时，只**更新已有疑难点行的「关联问题摘要」**（补充错因 / 易混点 / 已换讲法记录），不新建行；具体错题的明细另记入 `错题本/README.md`（CT 行）。
- **提问与交互约定**：不默认用户表述正确；用户关于某专题的说法如有偏差，先解析并给出规范表述，再记入疑难点。
- **不默认用户正确**：若用户反复提问源于概念误解，疑难点摘要应写明"易混点"而非照抄用户原话。

## 疑难点文档结构

`错题本/疑难点.md` 含：文档头 + 「一、疑难点记录」表（上述字段）+ 「二、复习建议」。新增记录只动记录表，不改动复习建议。
